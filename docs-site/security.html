Security

Law firms handle privileged information, so security is built into every layer: strong authentication, strict tenant isolation, encrypted transport, and audited platform operations.

Passwords & sign-in

  • Passwords are stored as salted scrypt hashes — never in plain text.
  • Minimum length 8 characters; changing your password requires the current one.
  • Accounts provisioned with a temporary password must set a new password on first login.
  • Sessions are signed, HTTP-only cookies; Sign out invalidates the session cookie immediately.
  • Superadmin (platform) logins are separated from firm logins — a superadmin cannot enter the firm UI via the normal login and vice versa.

Two-factor authentication (2FA)

  • Any user can enable TOTP 2FA under Settings → Security: scan the QR code with Google Authenticator, 1Password, or any TOTP app, and confirm with a code.
  • After every password login, a 6-digit code is required. 2FA state is re-challenged on each fresh login — codes are never "remembered" across logins.
  • Disable 2FA requires a valid current code.

Tenant isolation

  • Every record (client, case, invoice, document, message…) is bound to your firm. All queries filter by firm membership — another firm can neither read nor write your data.
  • Clients only reach their own records through the portal; internal notes stay internal.
  • Role checks apply on every operation server-side, not just hidden buttons in the UI.

Encryption & infrastructure

  • All traffic is HTTPS (TLS via Let's Encrypt); HTTP requests are redirected.
  • Calendar OAuth tokens are stored encrypted at rest.
  • Hosting is on Swiss infrastructure (data residency CH) with the database on a private network, unreachable from the internet.
  • File downloads are served through authenticated, path-checked routes.

Auditing & platform operations

  • Case timelines record every material action per matter.
  • Platform-level administrative actions (firm creation, plan changes, impersonation, announcements) are written to a superadmin audit log.
  • Support impersonation is explicit, temporary, audited, and clearly labelled in the UI while active.

Backups & availability

  • The production database runs with persistent volumes and scheduled dumps; ask support about the current backup and retention policy for your deployment.
  • On-premise/single-tenant deployment with an offline license is available for firms with strict hosting requirements — contact Cliavo.

Reporting a security issue

Found something? Email support@cliavo.com with "SECURITY" in the subject. Please do not test against other firms' data.
